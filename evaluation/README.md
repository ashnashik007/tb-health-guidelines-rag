# Health Guidelines RAG — Systematic Evaluation Framework

This directory contains the systematic evaluation framework for the **Health Guidelines RAG Assistant**, evaluating guideline accuracy, citation provenance, and strict hallucination prevention across 30 structured test cases based on official World Health Organization (WHO) tuberculosis guidelines.

---

## 1. Dataset Overview (`evaluation/dataset.json`)

The test suite comprises **30 structured test cases** categorized into 4 core clinical evaluation dimensions:

1. **Answerable Questions (Treatment Regimens & Care Guidelines)** (12 test cases)
   - Evaluates standard 6-month 2HRZE/4HR regimens, 4-month rifapentine-moxifloxacin regimens, pediatric dosing, fixed-dose combinations, and HIV coinfection ART timing.
2. **Insufficient-Evidence & Out-of-Scope Questions** (6 test cases)
   - Evaluates strict hallucination rejection. Tests non-TB medical conditions (Metformin, COVID boosters, Lyme disease, Guillain-Barré, lung cancer) and uncovered TB surgical details. The pipeline must return:
     > *"The provided guidelines do not contain enough information to answer this question."*
     The evaluator also recognizes the earlier exact fallback sentence for old reports.
3. **Potentially Conflicting & Evolving Recommendations** (6 test cases)
   - Evaluates guideline policy shifts: historical intermittent (3x weekly) therapy vs current daily therapy, hospital-based vs decentralized care, family vs trained lay provider support, and ethambutol omission in pediatric non-severe TB.
4. **Safety-Sensitive Clinical Contraindications & Toxicity** (6 test cases)
   - Evaluates clinical risk awareness: delaying ART in TB meningitis to prevent intracranial IRIS, acute jaundice/hepatotoxicity warning protocols, contraindication of streptomycin in pregnancy, and non-adherence risks.

### Dataset Schema Fields
- `id`: Unique identifier (`TC-01` to `TC-30`).
- `question`: The clinical guideline query.
- `question_category`: Categorical grouping for stratified analysis.
- `expected_answer`: Authoritative guideline-derived answer summary.
- `expected_source_document`: Target PDF file (`who_tb_treatment.pdf`, `who_tb_care.pdf`, or `None (Out of Guidelines)`).
- `verified_page_number_or_passage`: Explicit page reference from WHO module 4 guidelines, or marked with `[Needs Clinical Verification]` where expert clinical validation is required.
- `guideline_version_or_date`: WHO Consolidated Guidelines on Tuberculosis, Module 4 (2022).
- `expected_behavior`: `IN_GUIDELINES` or `STRICT_FALLBACK`.

## 2. Evaluation Runner (`evaluation/evaluate.py`)

The evaluation script directly interfaces with the existing RAG pipeline (`rag_service.py`) without modifying any backend code or exposing credentials:
- Queries vector database and LLM pipeline for each question.
- Captures generated answer, retrieved source files, page numbers, and text snippets.
- Measures response latency (seconds per query).
- Computes citation match and status classification.
- Exports a complete tabular report to `evaluation/evaluation_report.csv`.

## 3. How to Run the Evaluation on Windows

Open **PowerShell** and execute from the project root:

```powershell
cd "D:\New folder\health-rag"
& ".\backend\venv\Scripts\python.exe" ".\evaluation\evaluate.py"
```

*Note: The script reuses the existing backend virtual environment and packages (LangChain, ChromaDB, HuggingFace embeddings, Groq API).*

The script automatically switches to `backend/venv` if launched with another Python interpreter. Install backend dependencies into that environment with:

```powershell
Set-Location "D:\New folder\health-rag"
& ".\backend\venv\Scripts\python.exe" -m pip install -r ".\backend\requirements.txt"
```

## 4. How to Interpret `evaluation_report.csv`

The generated CSV report contains 12 columns:

| Column | Description |
| :--- | :--- |
| **`Test_ID`** | Identifier from `TC-01` to `TC-30`. |
| **`Question_Category`** | The clinical inquiry domain. |
| **`Question`** | The test question submitted to the RAG pipeline. |
| **`Expected_Behavior`** | `IN_GUIDELINES` (expected to answer) or `STRICT_FALLBACK` (expected to decline). |
| **`Expected_Source_Doc`** | Expected WHO document containing evidence. |
| **`Verified_Page_or_Passage`** | Page reference in the guidelines. |
| **`Actual_Answer`** | The verbatim answer generated by the model. |
| **`Retrieved_Sources`** | Semicolon-separated list of retrieved chunks with filenames and page numbers. |
| **`Citation_Match`** | `PASS` when the expected document appears among retrieved sources, `FAIL` for a missing/wrong-source or retrieval miss, or `N/A` for a strict fallback. |
| **`Evaluation_Status`** | Categorical outcome (see Status Codes below). |
| **`Needs_Clinical_Verification`** | `YES` or `NO` (flags items requiring licensed clinical review). |
| **`Response_Time_Sec`** | Round-trip query latency in seconds. |

### Evaluation Status Codes
- **`PASSED_STRICT_FALLBACK`**: Out-of-guideline question correctly identified; zero hallucination. Returned standard fallback text.
- **`PASSED_EXPECTED_SOURCE_MATCH`**: The expected source PDF was among the retrieved sources. This is a document-level citation check, not semantic verification of every answer claim.
- **`PASSED_SOURCE_MATCH_REQUIRES_CLINICAL_AUDIT`**: The expected PDF was retrieved, but the case requires clinical review.
- **`PASSED_GROUNDED_WITH_CITATION` / `PASSED_REQUIRES_CLINICAL_AUDIT`**: Legacy names used in older reports; they indicate expected-document presence and do not independently verify semantic entailment.
- **`CITATION_MISMATCH`**: Pipeline generated an answer but did not retrieve the anticipated primary guideline PDF in the top 4 chunks.
- **`MISSING_CITATION`**: A non-fallback answer was returned without any source citation.
- **`RETRIEVAL_ERROR`**: The vector database query failed before an answer could be evaluated.
- **`PROVIDER_ACCESS_ERROR`**: The LLM provider returned an access-denied/403 response.
- **`EXECUTION_ERROR`**: Another evaluation case failed during execution.
- **`FALSE_NEGATIVE_RETRIEVAL_MISS`**: Pipeline returned the fallback message for a question that was present in the guidelines (vector retrieval failure).
- **`FALSE_NEGATIVE_AFTER_EXPECTED_SOURCE_RETRIEVED`**: The answer fell back even though the expected source PDF was retrieved. This distinguishes source presence from a successful answer; it does not prove the retrieved passages support the question.
- **`FAILED_HALLUCINATION_DETECTED`**: Pipeline generated an ungrounded answer for an out-of-guidelines question.

The evaluator checks strict-fallback wording and expected source-document presence. It does not perform claim-level semantic entailment, so a source-document match is not proof that every generated claim is grounded. Unknown statuses are never counted as passes.
